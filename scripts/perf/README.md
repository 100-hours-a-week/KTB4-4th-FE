# 로컬 프로덕션 빌드 성능 측정 환경

로컬 프로덕션 빌드(`next start`)를 배포 환경과 비슷한 조건에서 측정하기 위한 Caddy 리버스 프록시 설정입니다. 배포 환경의 ALB와 같이 `/api/v1/*` 요청은 백엔드로, 나머지 요청은 Next.js 서버로 전달하고, 브라우저와는 HTTPS·HTTP/2로 통신합니다.

로컬 `next start`에는 개발 서버의 `/api/v1` rewrite가 적용되지 않아 브라우저의 API 요청이 404가 됩니다. 이 설정은 프로젝트 코드와 배포 이미지를 바꾸지 않고 이 문제를 해결합니다.

## 구성

| 주소                     | 역할                                                                |
| ------------------------ | ------------------------------------------------------------------- |
| `https://localhost:3000` | Caddy. 브라우저가 접속하는 측정 주소 (HTTP/2, Caddy 로컬 인증서)    |
| `http://localhost:3001`  | `next start`. Caddy가 `/api/v1/*`를 제외한 요청을 전달함            |
| `http://localhost:8080`  | 로컬 백엔드. Caddy가 `/api/v1/*` 요청을 전달함 (SSE 응답 즉시 전달) |
| `http://localhost:3000`  | `npm run dev`. 로그인할 때만 Caddy 대신 잠시 실행함                 |

Caddy는 `next.config.ts`가 붙이는 `Strict-Transport-Security` 헤더를 응답에서 제거합니다. 이 헤더가 브라우저에 저장되면 로그인용 `http://localhost:3000` 개발 서버에 접속할 수 없기 때문입니다.

## 준비

처음 한 번만 진행합니다.

```bash
brew install caddy
```

Caddy를 처음 실행하면 로컬 인증 기관이 만들어지고 macOS 키체인에 신뢰 등록을 요청합니다. 비밀번호 입력 창이 뜨면 입력합니다. 자동 등록이 되지 않았다면 Caddy를 실행한 상태에서 다른 터미널에서 `caddy trust`를 실행합니다. Chrome이 켜져 있었다면 완전히 종료한 뒤 다시 엽니다.

## 실행 순서

로그인은 백엔드가 로그인 후 `http://localhost:3000`으로 돌아오므로 개발 서버에서 진행하고, 로그인 쿠키를 그대로 사용해 측정 환경으로 넘어갑니다. 쿠키는 포트와 http·https를 구분하지 않고 `localhost` 단위로 저장됩니다.

1. 로컬 백엔드를 `8080` 포트로 실행합니다.
2. 측정할 코드로 프로덕션 빌드를 만듭니다. `NEXT_PUBLIC_*` 값은 빌드할 때 코드에 들어가므로, 목업 데이터를 쓰려면 빌드 명령에 지정합니다.

   ```bash
   NEXT_PUBLIC_USE_MOCK_DATA=true npm run build
   ```

3. 개발 서버로 로그인합니다. `npm run dev` 실행 후 `http://localhost:3000`에서 로그인하고, 로그인이 끝나면 개발 서버를 종료합니다(`Ctrl+C`).
4. 다른 터미널에서 프로덕션 서버를 실행합니다.

   ```bash
   npm run start -- -p 3001
   ```

5. 다른 터미널에서 Caddy를 실행합니다.

   ```bash
   caddy run --config scripts/perf/Caddyfile --adapter caddyfile
   ```

6. Chrome에서 `https://localhost:3000`에 접속해 측정합니다. DevTools Network 탭의 Protocol 열이 `h2`인지 확인합니다.

종료할 때는 Caddy와 `next start` 터미널에서 각각 `Ctrl+C`를 누릅니다.

## 다시 로그인하기

리프레시 토큰이 만료되면 측정 환경에서 `/login`으로 이동합니다. 측정 환경에서는 로그인할 수 없으므로 다음 순서로 다시 로그인합니다.

1. Caddy만 종료합니다(`Ctrl+C`). `next start`는 그대로 둡니다.
2. `npm run dev` 실행 후 `http://localhost:3000`에서 로그인하고, 개발 서버를 종료합니다.
3. Caddy를 다시 실행합니다.

## 측정 규칙

토큰 재발급이나 재로그인이 섞이면 요청 수와 대기 시간이 늘어나 측정값이 달라집니다.

- 측정을 시작하기 직전에 새로 로그인합니다.
- 측정 중 Network 탭에 `401` 응답, `/api/v1/auth/csrf`, `/api/v1/auth/refresh` 요청이 보이면 그 회차는 무효로 하고 같은 시나리오를 처음부터 다시 측정합니다.
- `/login`으로 이동했다면 측정을 멈추고 [다시 로그인하기](#다시-로그인하기) 후 해당 시나리오를 처음부터 다시 측정합니다.
- 무효로 한 회차와 이유(토큰 재발급, 재로그인)를 측정 기록에 남깁니다.

## 배포 환경과의 차이

| 항목      | 배포 환경            | 측정 환경                                       |
| --------- | -------------------- | ----------------------------------------------- |
| 경로 분기 | ALB Listener Rule    | Caddy `handle /api/v1/*`                        |
| 인증서    | 공인 인증서          | Caddy 로컬 인증 기관 인증서                     |
| HSTS 헤더 | 적용됨               | 제거됨                                          |
| 네트워크  | 실제 네트워크        | 로컬 연결. 필요하면 DevTools 네트워크 제한 사용 |
| 로그인    | 서비스 주소에서 직접 | 개발 서버에서 로그인한 뒤 쿠키를 이어서 사용    |

## 정리

측정 작업을 모두 마친 뒤 키체인에서 Caddy 인증 기관 신뢰를 해제합니다.

```bash
caddy untrust
```
