## 1. PR 제목 컨벤션

PR 제목은 커밋 메시지와 동일한 Conventional Commits 형식을 사용합니다.

type: 작업 제목 (#이슈번호)

예시:

chore: 프로젝트 초기 설정 (#89)
feat: 로그인 화면 구현 (#90)
fix: 로그인 오류 처리 수정 (#91)

Squash Merge 시 PR 제목이 최종 커밋 메시지가 될 수 있으므로 반드시 이 형식을 지킵니다.

PR 제목은 브랜치의 전체 작업을 포괄해야 합니다. 작업 범위가 달라졌다면 최종 변경 사항을 기준으로 제목을 다시 작성합니다.

## 2. PR 본문 컨벤션

다음 템플릿을 사용합니다. PR 본문 작성시 종결어미는 -음, -임, -함 등을 사용해서 간단하게 작성하고, 가능하다면 명사형으로 끝나도록 작성해주세요.
코드 내에서 TODO 주석을 통해 추후 작업을 명시한 경우 추가 논의에 작성해주세요.

### 구현 배경

- 이 작업이 필요한 이유를 간단하게 작성

### 작업 사항

- 실제로 변경한 작업을 작성 (커밋해시)
- 같은 목적의 파일은 하나의 작업으로 묶어서 작성 (커밋해시)

### 추가 논의

- 리뷰가 필요한 사항이나 결정되지 않은 내용 작성
- 추가 논의가 없다면 `- 없음`으로 작성
- TODO 주석을 작성한 파일명과 함께 추후에 작업해야 한다는 점을 명시

### 이슈

- 브랜치에 기재된 이슈번호와 함께 Closes #이슈번호 형태로 작성

### 구현 배경

- 프런트엔드 코드 품질과 자동 릴리스 기준을 통일하기 위한 설정 필요

### 작업 사항

- ESLint·Prettier 코드 품질 규칙 설정 (a93a26e)

- Closes #1

## 3. PR 제출 전 검증

PR을 작성하거나 추천하기 전에 다음 명령을 실행하고 결과를 확인합니다.

npm run format:check
npm run lint

검사가 실패하면 실패 원인을 수정한 뒤 다시 실행합니다. 실행하지 못한 검사가 있다면 PR 본문이나 최종 보고에서 그 이유를 명확히 설명합니다.

## 4. 결과 보고

브랜치, 커밋 또는 PR 작업을 수행한 경우 다음 내용을 사용자에게 알려주세요.

- 생성하거나 사용한 브랜치명
- 생성한 커밋 메시지와 커밋 해시
- PR 제목과 URL
- 실행한 검증 명령과 결과
- 남아 있는 오류나 추가 논의 사항

사용자가 이름이나 메시지 추천만 요청했다면 실제 브랜치 생성, 커밋, push 또는 PR 수정은 하지 말고 추천 내용만 제공하세요.
사용자가 PR 작성을 요청했다면 임의로 작성하지 말고 제목, 본문을 각각을 바로 복사할 수 있는 형태로 제공하세요. 절대 먼저 직접 작성하지 마세요.
